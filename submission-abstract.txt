1. PROPOSED TITLE
--------------------------------------------------------------------------------
Fleet Commander: AI-Driven Autonomous IoT Fleet Management with Predictive
Maintenance, Self-Healing, and Smart Energy Arbitrage


2. WHAT PROBLEM IS BEING SOLVED?
--------------------------------------------------------------------------------
Managing IoT devices at scale is broken. Fleet operators face four crises:

(1) Manual operations don't scale. Pushing firmware updates to 10,000+
    devices using SSH or USB takes weeks. A single bad update can brick an
    entire fleet.

(2) Failures are reactive, not predictive. Devices fail silently. Operators
    discover dead sensors or crashed gateways only after they stop reporting
    — losing days of data and revenue.

(3) No self-healing. When a device goes rogue (wrong firmware, config drift),
    humans must manually fix each unit. At scale this is impossible.

(4) Edge energy is wasted. EV fleets and battery-backed sensors have no
    intelligence about when to charge or discharge based on grid prices.

Fleet Commander solves all four with a unified, AI-driven platform that is
already built, tested, and running with real MQTT-connected devices.


3. PROJECT DETAILS
--------------------------------------------------------------------------------
Fleet Commander is a production-grade, open-source IoT fleet management
system running 5 containerized services orchestrated via Docker Compose:

  Backend (FastAPI, 99 endpoints, 16 database tables)
  + Mosquitto MQTT broker
  + Prometheus (30+ metrics)
  + Grafana dashboards
  + Device simulator (5 virtual devices, 20% OTA failure rate)

--- Six AI Agents ---

1. OTA Campaign Agent — Canary-based rollout planner (10% -> 50% -> 100%)
   with automatic rollback on failure
2. Fleet Health / Anomaly Agent — Detects offline devices, signal
   degradation, revenue drops; triggers multi-channel alerts
3. Device Grouping Agent — Clusters devices by firmware, signal strength,
   and geographic proximity
4. V2G Dispatch Agent — Optimal charge/discharge using real spot-price data
5. Device Onboarding Agent — Conflict detection (MQTT IDs, IPs, names)
   with auto-registration and firmware recommendations
6. Predictive Maintenance Agent — Trend analysis on telemetry predicting
   failures before they happen

--- 13 Advanced Features ---

- OTA firmware updates with SHA256 + Ed25519 signing + auto-rollback
- Aegis Auto-Remediation Engine (8 rules, dead-letter queue, dry-run)
- Alerting pipeline (dedup, cooldown, escalation, Slack/Email/Webhook)
- Scheduled OTA campaigns with blackout hours and canary %
- Offline command queue with reconnect delivery
- Device shadow / digital twin (AWS IoT pattern)
- Geofencing with circle/polygon and live Leaflet map overlays
- Device lifecycle (active > maintenance > decommissioned, QR-claim)
- Bulk CSV import for mass provisioning
- Webhook / event stream with HMAC signing
- RBAC (5 roles: user, admin, operator, viewer, fleet_manager)
- Audit log for every mutating action
- V2G energy arbitrage with real spot prices

--- Test Coverage ---
91 unit tests + 40 end-to-end integration tests — all passing.
Simulator runs 5 virtual devices (3 EVs) with realistic failure rates.


4. BOARD(S) PLANNED
--------------------------------------------------------------------------------
Primary:   M5Stack CoreS3-SE
Secondary: MAX32630FTHR
Tertiary:  Arduino Uno Rev3


5. ROLE OF EACH BOARD
--------------------------------------------------------------------------------
M5Stack CoreS3-SE (Primary — Edge Gateway + Local AI):
  - Runs the MQTT client for OTA updates, heartbeat reporting, command
    reception via ESP32-S3 dual-core processor
  - 2-inch IPS screen shows real-time device status, geofence alerts,
    OTA progress bar, energy arbitrage recommendations
  - Local AI inference using Edge Impulse to classify sensor anomalies
    before sending to cloud — reduces bandwidth by 60%
  - BLE bridge to collect data from MAX32630 sensor node

MAX32630FTHR (Secondary — Remote Sensor Node):
  - Ultra-low power operation on CR2032 coin cell
  - Deep-sleep scheduling: wakes every 15 minutes
  - Reads temperature, humidity, vibration for predictive maintenance
  - Sends data via HC-05 BLE to CoreS3-SE gateway

Arduino Uno Rev3 (Tertiary — Actuator Controller):
  - Controls physical relays (siren, cutoff switch, LEDs)
  - Triggered remotely through Fleet Commander platform via CoreS3-SE

This 3-tier architecture demonstrates cloud intelligence (backend), edge
computing (CoreS3-SE), and constrained devices (MAX32630FTHR) working
together as a real fleet management system.
