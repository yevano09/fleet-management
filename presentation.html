The Problem

  • Firmware updates brick devices — no safe rollback
  • No predictive maintenance — failures discovered on road
  • Cold-chain cargo lost to silent temperature breaches
  • Devices go offline — commands are lost
  • "AI" in fleet tools is a slope heuristic with no eval gate

Architecture

Data Plane

Devices (simulator, ESP32, UNO Q) → Mosquitto MQTT → FastAPI ingest → batch worker → SQLite/PostgreSQL. OBD-II, BMS, cargo, heartbeat feeds.

Intelligence

ML registry (IsolationForest) → predictions with model_version → AlertEngine (dedup/escalate) → work orders → twin view. Aegis auto-remediation.

Edge

ESP32 threshold engine · Edge gateway (RPi) · Arduino UNO Q (STM32 + QRB Linux running full ONNX model) · offline outbox with replay.

Observability

50+ Prometheus metrics · Grafana dashboards · Dashboard UI (Chart.js, Leaflet map, copilot chat) · Audit log · Webhook event stream.

Live: OTA Update + Auto-Rollback

POST /ota/trigger publishes signed OTA commands over MQTT. Devices report downloading → applying → verifying → success. 20% hit a hash mismatch — the state machine cascades hash_mismatch → rollback → rolled_back and restores the previous firmware. Zero operator intervention.

Predictive Maintenance — Real ML

POST /predictive/scan?model=auto runs a seeded IsolationForest (200 trees, normal-window trained). Attribution across signal/thermal/TPMS/fuel/DTC groups. model_version stamped on every prediction. Eval harness gates promotion: TPMS legacy lead 0/10, model beats it.

The AIoT Loop

Predict → Alert → Work Order → Twin

  • Fault injection → ML flags risk with model_version
  • AlertEngine dedups, cools down, escalates
  • 3rd escalation → auto-opens templated work order
  • Operator closes with resolution + parts + cost
  • MTTR histogram · GET /twin/{id} merges health + risks + WO

Smart Cargo & Copilot

CargoProfile per vehicle · +/cargo telemetry (bay temp, humidity, door, shock) · TTS estimator with door penalty · shock classifier (HARD_DROP, CARGO_COLLISION).

Copilot: CrewAI + privacy layer. 7 read-only tools. PII redacted, GPS degraded, VINs masked. Mock brain default — no keys needed. Try the chat bubble.

Edge AI & Arduino UNO Q

The UNO Q collapses sensor-node + ESP32 + RPi-gateway into one board. STM32 MCU samples DHT22+MPU6050 @2Hz → Serial1 → QRB Linux SoC runs the full IsolationForest ONNX (same model as cloud). Verdicts published to iot/fleet/{id}/edge, never raw samples. Offline outbox with replayed:true.

While the board is in transit: python edge/uno_q_gateway.py falls back to simulated thermal drift. Wokwi runs the exact STM32 sketch.
